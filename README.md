# МАХ Кейсы

Клиентское мини-приложение для студенческих проектных задач и вакансий в мессенджере МАХ. В интерфейсе предусмотрены два сценария: студент заполняет профиль, откликается на задачи, ведёт портфолио и общается с заказчиком; работодатель оформляет компанию и задачи, рассматривает отклики и взаимодействует с исполнителем.

> Этот документ описывает текущее состояние репозитория. Некоторые зависимости и переменные окружения оставлены как заделы, но ещё не подключены к рабочим сценариям.

## Архитектура и решения

- **Клиентское SPA.** Точка входа `src/main.tsx` монтирует React-приложение в `#root`; сборка Vite выдаёт статические файлы. Отдельный backend/API в проекте не настроен.
- **Один корневой маршрутизатор.** `src/App.tsx` выбирает экран на основе пользователя и активной вкладки, а также управляет видимостью модальных окон. Отдельная библиотека маршрутизации не используется.
- **Общее состояние через Context.** `AppProvider` в `src/context/AppContext.tsx` хранит пользователя, профили, вакансии, отклики, сделки, сообщения, проекты и отзывы. Функции контекста реализуют регистрацию, вход, создание задачи, отклик, чат, этапы сделки и отзывы.
- **Ролевые интерфейсы.** В приложении есть роли `student` и `employer`, наборы вкладок и отдельные экраны для каждой роли. Исходные наборы тестовых пользователей и данных пусты.
- **Типизированная предметная модель.** Интерфейсы и объединения ролей, статусов, сделок и сообщений находятся в `src/types/index.ts`.
- **Хранение в браузере.** Сейчас источником сохранённых данных является `localStorage`, запись синхронизируется эффектами React Context. Это локальное хранилище конкретного браузера, а не общее хранилище для нескольких пользователей или устройств.
- **Интеграция с MAX через адаптер.** `src/services/maxBridge.ts` оборачивает доступные методы `window.WebApp` для haptic-откликов, платформы, диплинка, кнопки Back и шаринга. Вне MAX используются ограниченные браузерные fallback-варианты. SDK подключён скриптом в `index.html`.
- **Дизайн для мобильного WebView.** Интерфейс имитирует экран смартфона на широком экране и переключается на полноэкранное представление на узком; стили собраны из Tailwind-классов и базовых правил в `src/index.css`.
- **DatabaseService не является текущим хранилищем контекста.** В `src/services/db.ts` есть заготовка IndexedDB с методами, работающими через `localStorage`, но `AppContext` её не импортирует. IndexedDB в рабочем потоке приложения сейчас не используется.

## Структура проекта

```text
.
├── index.html                 # HTML, шрифты и MAX WebApp SDK
├── metadata.json              # Метаданные мини-приложения
├── package.json               # Зависимости и npm-команды
├── tsconfig.json              # Параметры TypeScript
├── vite.config.ts             # React, Tailwind, alias и dev server
└── src/
    ├── main.tsx               # Точка входа React
    ├── App.tsx                # Компоновка экранов и модальных окон
    ├── index.css              # Глобальные стили
    ├── context/AppContext.tsx # Состояние, бизнес-действия, сохранение
    ├── services/
    │   ├── db.ts              # Не подключённый к Context сервис хранения
    │   └── maxBridge.ts       # Адаптер MAX WebApp API
    ├── types/index.ts         # Типы сущностей и состояний
    └── components/
        ├── auth/              # Регистрация и вход
        ├── student/           # Экраны студента
        ├── employer/          # Экраны работодателя
        ├── max/               # Заголовок, статус и нижняя навигация
        ├── modals/            # Диалоги и карточки поверх экранов
        └── common/            # Общие компоненты
```

В конфигурации TypeScript алиас `@/*` указывает на корень репозитория. Vite определяет alias `@` также на корень проекта.

## Запуск

Требуется Node.js, совместимый с Vite 8, и npm. Рекомендуется актуальная LTS-версия Node.js.

В PowerShell из папки `HackaTonMax2026`:

```powershell
npm install
npm run dev
```

Сервер Vite слушает порт `3000` и адрес `0.0.0.0`; обычно приложение доступно по адресу `http://localhost:3000`.

Другие команды:

```powershell
npm run lint    # Проверка TypeScript: tsc --noEmit
npm run build   # Production-сборка в dist/
npm run preview # Предпросмотр собранной версии
```

`npm run clean` использует POSIX-команду `rm -rf` и может не выполняться в стандартном PowerShell без совместимой оболочки. Удаление `dist` для чистой сборки можно выполнить командой `Remove-Item -Recurse -Force dist`.

## Переменные окружения

Файл `.env.example` содержит шаблон, но наличие ключа в нём само по себе не подключает функцию в приложение.

| Переменная | Назначение по шаблону | Использование сейчас |
| --- | --- | --- |
| `GEMINI_API_KEY` | Ключ Gemini API | В исходниках вызов API и чтение этой переменной не реализованы. Не добавляйте секрет в клиентский bundle. |
| `APP_URL` | Публичный адрес приложения | Исходники переменную не читают. Для ссылки на опубликованное приложение используется URL хостинга/MAX. |
| `DISABLE_HMR` | Управляет HMR и file watching в `vite.config.ts` | Используется конфигурацией Vite через `process.env`; для PowerShell задаётся перед запуском: `$env:DISABLE_HMR="true"; npm run dev`. Обычно оставьте не заданной. |

`GEMINI_API_KEY` и `APP_URL` в `.env.example` сейчас являются только документационными заготовками. `.env*` исключены из Git, кроме `.env.example`. Для будущих секретов нужен серверный слой: Vite-переменные с префиксом `VITE_` попадают в клиентский код и не подходят для секретных ключей.

## Работа с данными

### Сущности

Ключевые сущности определены в `src/types/index.ts`:

- пользователь и роль;
- профиль студента и профиль работодателя;
- вакансия и отклик;
- сделка и сообщения чата;
- проект портфолио и отзыв.

### Локальное сохранение

`AppContext` загружает JSON из `localStorage` при создании состояния и сохраняет обновления эффектами. Используемые ключи:

| Ключ | Данные |
| --- | --- |
| `max_db_users` | Зарегистрированные пользователи |
| `max_cases_user` | Текущая сессия пользователя |
| `max_student_profiles`, `max_employer_profiles` | Профили по ролям |
| `max_vacancies`, `max_applications` | Задачи и отклики |
| `max_projects`, `max_reviews` | Портфолио и отзывы |
| `max_deals`, `max_messages` | Сделки и сообщения |
| `max_cases_schema` | Версия локальной схемы |

При изменении `DB_SCHEMA_VERSION` в AppContext приложение удаляет перечисленные ключи и записывает новую версию. Поэтому изменение версии схемы сейчас приводит к очистке сохранённых локальных данных; перед проверкой новой версии не храните в браузере нужные данные.

### Основной поток сделки

1. Работодатель создаёт вакансию.
2. Студент откликается; приложение сохраняет отклик, создаёт сделку в стадии `negotiation` и начальные сообщения.
3. Переписка хранится локально. Согласие переводит сделку в `in_progress`.
4. Студент может передать реквизиты, сделка переходит в `waiting_payment`.
5. Подтверждение оплаты переводит её в `completed`, создаёт проект в портфолио и позволяет оставить отзыв.

Это моделирование процесса в интерфейсе. Фактические платежи, доставка сообщений между пользователями и серверная проверка состояний не подключены.

## Проверка проекта

Автоматические unit-, интеграционные и E2E-тесты в `package.json` не настроены. Проверяйте изменения в следующем порядке:

1. Установить зависимости: `npm install`.
2. Проверить TypeScript: `npm run lint` (`tsc --noEmit`).
3. Проверить production-компиляцию: `npm run build`.
4. Проверить собранный вариант локально: `npm run preview` и открыть URL, который выведет Vite.
5. Выполнить ручной smoke-check в браузере: зарегистрировать студента, заполнить профиль, выйти, зарегистрировать работодателя, создать вакансию, вернуться в профиль студента, откликнуться, открыть чат и пройти этапы сделки до завершения.
6. Обновить страницу и проверить восстановление данных из `localStorage`; проверить, что в приватном окне/другом браузере данные не появляются.
7. Для MAX проверить приложение в тестовом WebView: загрузку SDK, безопасные HTTPS-ссылки, нативную навигацию, haptic feedback и шаринг. В обычном браузере проверяются только fallback-сценарии.

## Ограничения и безопасность

- Нет backend, общей базы данных, API, реальной аутентификации и серверной авторизации ролей.
- Пароль сохраняется в поле `passwordHash` без хеширования и в виде открытого текста в `localStorage`. Это небезопасно; текущую авторизацию следует считать демонстрационной.
- Профили, платежные реквизиты, отклики и сообщения доступны через инструменты браузера и могут быть изменены пользователем.
- `localStorage` привязан к origin и браузеру, не предназначен для синхронизации между участниками и ограничен по объёму.
- В `.env.example` и `metadata.json` упоминается Gemini/server-side API, но соответствующая серверная интеграция не обнаружена в исходниках.
- Переменная `APP_URL`, Express и `DatabaseService` пока не встроены в рабочий сценарий приложения.
- Начальные массивы пользователей и предметных данных пусты: после очистки хранилища необходимо заново зарегистрировать пользователей и создать данные для демонстрации.

Перед реальным запуском с пользователями необходимы серверное хранение, безопасная авторизация с хешированием паролей, проверка прав на сервере, миграции данных, валидация входных значений и отдельная интеграция с платёжным провайдером.

## Сборка и публикация

Команда `npm run build` создаёт статические файлы в `dist/`. Для локальной проверки используйте `npm run preview`. Для публикации разместите содержимое `dist/` на поддерживающем HTTPS статическом хостинге и укажите HTTPS-адрес в настройках мини-приложения MAX.

Для локальной сборки или хостинга обязательные значения `.env.example` не требуются. В MAX загружается страница из `dist/`; клиентские данные всё равно останутся локальными, пока не будет реализован backend.
